# Week2Speak: project handoff

Week2Speak (week2speak.com) is an English-speaking practice site for Spanish-speaking adults. It is a static, multi-page site: Python scripts generate plain HTML, CSS and JavaScript into `w2s-site/dist/`, and that folder is what you deploy. No framework, no server code and no database. Learner progress lives in the learner's browser.

This package is the exact state of the site on 17 November 2026. A build from this folder was compared file by file with the live build and matched in every one of its 41 files, apart from the build date stamp. Both test suites passed on it (see section 9).

---

## 1. Quick start

You need **Python 3.10 or newer** and **Node.js 18 or newer** (built and tested with Python 3.13 and Node 22). No Python packages are needed.

```bash
npm install                        # installs Playwright, used only by the tests and tools
npx playwright install chromium    # the browser Playwright drives
npm run build                      # writes w2s-site/dist/
npm run serve                      # http://localhost:8765
```

In a second terminal, with the server running:

```bash
npm test                 # all 11 pages: console errors, broken links, sideways scroll
npm run test:buddies     # Speech Mode and the Language Buddies: 20 checks
```

On Windows, run the commands inside `package.json` by hand (or use WSL), because `SITE_URL=... python3` is Unix shell syntax.

## 3. How the build works

```
w2s-show/showcase.pre-sprint.html
        |  apply_sprint.py  (+ sprint_content.py, then apply_more.py)
        v
w2s-show/showcase.html  and  w2s-site/data.json
        |  sitebuild.py  (+ seo_content, privacy_content, body_parts, buddy_block, extra.css, config.json)
        v
w2s-site/dist/   11 pages, assets, sitemap, robots.txt, llms.txt, _headers, manifest, 404
```

- **apply_sprint.py always starts again from `showcase.pre-sprint.html`**, so it can be re-run any number of times. Change app behaviour by editing `showcase.pre-sprint.html`, `apply_sprint.py` or `apply_more.py`. Never edit `showcase.html`, because the next build overwrites it.
- Each patch uses `rep(old, new)`, which fails loudly when the text it expects is not found exactly once. If a build stops with `MISSING:` or an assertion, the source text that patch targets has changed.
- **sitebuild.py** takes the app apart: styles become `assets/site.css` (with `extra.css` and the Speech Mode styles added), the first script becomes `assets/app.js`, the home-page script becomes `assets/home.js`, and each room becomes its own page with its own URL, title, description, canonical link and JSON-LD.
- Hash links (`#speak`) become real paths (`/speech-mode/`). Links that need to open a page in a given state (a game, a clip, a scene) use `data-go` and pass the state through `sessionStorage` key `w2s.go`.
- `SITE_URL` sets the absolute URLs in the sitemap, canonical links and structured data. It defaults to `https://week2speak.pages.dev`; `npm run build` sets it to `https://week2speak.com`.
- Every build stamps assets with the build time (`?v=YYYYMMDDHHMM`) so browsers fetch the new files.

### Settings (`w2s-site/config.json`)

```json
{"owner": "Mei Gabriela Parrablanco", "formKey": "", "whatsapp": ""}
```

- `formKey`: a Web3Forms access key. When set, the Join form posts to `api.web3forms.com`. It is empty today, so the form shows "Sign-ups open soon".
- `whatsapp`: number with country code, digits only. When set, the form opens WhatsApp with the message filled in.

## 4. Existing features

- **Speech Mode**: scenes Café order, Meet someone new, Airport check-in, Job interview, Chat about yesterday, Coffee chat: opinions. Each reply earns XP. Mistakes typical of Spanish speakers (from `data.json`) get a correction card. Help me gives up to three levels: a sentence starter, then words to use, then a model sentence with Hear it. A Free talk scene with an AI tutor only appears where an AI capability exists (`cap.sample`); on the static site it is hidden and the scenes are scripted.
- **Games**: five games with a pack for each Sprint day. Each ends with the learner saying the answer.
- **Shadowing**: listen, speak along, speak alone, with words lighting up in time.
- **7-Day Sprint**: a Today hub, six tasks a day that tick themselves when done, a Day 1 and Day 7 recorder for a before-and-after comparison, and the 2-minute talk timer.
- **Course**: seven lessons.
- **XP, streak, mistake log** shared across pages.
- **SEO**: per-page titles and descriptions, canonical links, JSON-LD (organisation, breadcrumbs, FAQ, course, video), `sitemap.xml`, `robots.txt`, `llms.txt`.
- **Privacy**: every asset is self-hosted (fonts, GSAP, three.js, models). The site makes no requests to other domains, except the Join form when a Web3Forms key is set. `_headers` limits microphone use to the site itself.

## 5. Speech: voice out, voice in

All of this is browser speech; there is no audio file and no server.

**Voice out (`Voice` in the app script).**
- `Voice.speak(text, {rate, onWord, onEnd})` uses the browser's `speechSynthesis`.
- It picks a voice in the chosen accent (`us`, `gb`, `au`). It prefers a voice of the current Buddy's gender (`window.W2S_BUDDY_GENDER`, `f` or `m`), matched by voice name, and falls back to any voice in that accent.
- Not every browser reports word boundaries, so a planned timing (`plan()`) moves the word highlight at speaking pace when they are missing. With no voice at all, the words still light up.
- Browsers only allow speech after a tap. That is why Speech Mode opens with "Start talking", and why `window.W2S_HOLD` stops the first line from being spoken on page load.

**Voice in (`Mic`).**
- Uses the Web Speech API (`SpeechRecognition` or `webkitSpeechRecognition`). Where it exists, `<html>` gets the class `has-mic`.
- The mic button streams the words into the text field and sends the sentence when the learner stops.
- Where it does not exist, the mic is hidden and the text field leads.

**Events the Buddies listen to.** These are fired on `window`; keep this contract.

| Event | When | Detail |
|---|---|---|
| `w2s:speak` | a line starts | `{text}` |
| `w2s:word` | each word | `{word, i}` |
| `w2s:speakend` | the line ends or is stopped | |
| `w2s:mic` | mic on or off | `{on}` |
| `w2s:good` / `w2s:oops` | a reply without or with a mistake | |
| `w2s:help` | Help me | |
| `w2s:done` | scene complete | `{bonus}` |
| `w2s:buddy` | Switch Buddy | `{id, gender}` |

The Speech Mode screen adds `w2s:start` (Start talking or Play again), `w2s:replay`, `w2s:mute`, `w2s:shown` and `w2s:layout` (keyboard open or closed).

## 6. The Speech Mode screen (`buddy_block.py`)

- **Phone (under 900px):** one screen with no page scroll.
  - Header is one 48px row.
  - The stage fills the screen down to a reply bar pinned at the bottom: 76px with a 64px mic, the text field with Send, and the Help me chip.
  - A subtitle with word highlighting and a replay button sits over the bottom of the stage. Correction, Help me and Scene complete cards sit above it.
  - One button opens a bottom sheet with the scene list, conversation, accent, sound and show settings, and the session tally.
  - Switch Buddy and sound are on the stage.
  - When the keyboard opens (measured with `visualViewport`), the stage shrinks to about a third and the bar stays visible.
- **Desktop:** the stage takes about half the width and the full height; the conversation and settings sit beside it.
- **State is on the container:** `#sm[data-state]` is `landing`, `speaking`, `turn` or `done`; `data-mic` is `on` or `off`; the class `kb` means the keyboard is open; `sheet-open` means the sheet is open.
- **Mirror, not replacement:** the screen does not change the app's own scene logic. It reads the conversation list (`#chat`) to fill the subtitle and cards. The original controls (`#speakInput`, `#speakSend`, `#speakMic`, `#helpBtn`, `#missions`, `#chat`, the tally) keep their ids.
- **3D loads late:** `buddies.js` is loaded as a module after the page has loaded and the browser is idle. Until then, and on devices without WebGL 2, the static pictures (`assets/buddies/ruby.webp`, `max.webp`) are shown.

## 7. The 3D Language Buddies

**Who they are.** Display names Ruby (female, from London, blue rain jacket, tea flask, yellow headphones) and Max (male, from New York, varsity jacket, coffee cup). The internal ids stay `mila` (Ruby) and `rio` (Max) so saved choices keep working.

**Files.**
- `w2s-site/buddies.js`: the runtime.
- `w2s-site/buddy-gen/`: the generator.
- `w2s-site/buddy-models/README.md`: the model spec.
- The build writes `dist/assets/buddies/ruby.glb`, `max.glb`, a gzipped copy of each (`.glb.gz`) and the two `.webp` pictures, plus `assets/vendor/three-0.170.0.module.min.js`, `GLTFLoader-0.170.0.js` and `BufferGeometryUtils-0.170.0.js`.

**Loading.**
- The page fetches `<name>.glb.gz` and inflates it with `DecompressionStream`, so the download is about 0.95 MB on any host. It falls back to the plain `.glb`.
- Only the current Buddy is downloaded; the other one loads when the learner switches.

**How the built-in models are made.**
- `buddy-gen/gen.cjs` sculpts each character from smoothly blended distance fields, so the head, jacket and hands are each one continuous surface. It turns them into meshes, colours each vertex, rigs them and writes a GLB with morph targets. No textures and no dependencies.
- `node buddy-gen/gen.cjs` rebuilds both in about 4 seconds.
- Each is about 1.8 MB raw, about 0.95 MB gzipped, and about 85,000 triangles in about 27 draw calls.

**Rig "w2s-1" (the built-in models).**
- Plain nodes with no rest rotation: `Hips`, `Spine`, `Neck`, `Head`, `Left/RightArm`, `Left/RightForeArm`, `Left/RightHand`, `Left/RightUpLeg`.
- Face nodes `EyeL/R`, `LidL/R`, `LowLidL/R`, `BrowL/R`, plus `Pony` and `Prop`.
- Morph targets `jawOpen`, `mouthPucker`, `mouthWide`, `mouthSmile`, `mouthFrown`.
- Scene extras: `{"w2s": {"rig": "w2s-1", height, faceWidth, lidOpen, lidClosed, lowLid}}`.

**What the runtime does.**
- **Lip sync:** each `w2s:word` is turned into a few mouth shapes from its letters. Between words, a talking loop runs. The mouth closes when the line ends. This also runs in reduced-motion mode.
- **Spin:** drag to spin, flick for inertia, and the Buddy settles facing front.
- **Pokes:** tapping the face, hair, torso, arm, prop or legs gives one of ten reactions: giggle, boop, hair flick, tickle, shrug, wave, sip, startled, tap dance, spin jump. The same reaction never comes twice in a row, and the least recent one comes first. Five quick pokes give a side-eye.
- **Hidden extras:** double-tap the face for sunglasses, long-press for a big head, three full turns for the helicopter.
- **Conversation:** a talking pose with hand gestures, a listening pose while the mic is on, a nod and confetti for a good reply, a look down then a nod for a correction, a thinking pose for Help me, and a celebration when the scene is done.
- **Life:** blinking with the eyelids, breathing, and eyes and head that follow the pointer or last touch.
- **Switch Buddy:** the old Buddy spins out, the new one pops in and waves. The switch is saved, announced to screen readers and works from the keyboard.
- **Sound:** small synthesised effects, silent until the first tap, with a toggle (`w2s.buddyMute`).
- **Performance:**
  - Pixel ratio is capped at 2, and rendering stops when the stage is off screen or the tab is hidden.
  - If the frame rate stays under 40 for two seconds, quality steps down: pixel ratio 2, then 1.5, then 1, then shadows off.
  - On a slow device the animation takes several small steps per drawn frame, so lip sync stays in time with the voice.
- **Measuring:** add `?fps=1` to the Speech Mode URL to see frames per second, draw calls, triangles, the quality step and the graphics chip.
- **Debug handle:** `window.W2SBuddies` (`ready`, `id`, `fps`, `mouth`, `log`, `poke(part)`, `react(name)`, `view({rot, frame, blink})`, `snap()`, `setQuality(n)`).

## 8. Bringing in your Blender characters

Full spec: `w2s-site/buddy-models/README.md`.

1. **Model in Blender:** about 2.2 units tall (1 unit = 1 metre), feet on the ground at the origin, facing +Y in Blender (which becomes +Z in glTF), A-pose, mouth closed, eyes open. Keep each character under 2 MB.
2. **Face shape keys:** add shape keys with ARKit names (`jawOpen`, `mouthPucker`, `mouthFunnel`, `mouthSmileLeft`/`Right`, `mouthFrownLeft`/`Right`, `mouthStretchLeft`/`Right`, `eyeBlinkLeft`/`Right`) or Oculus viseme names (`viseme_aa`, `viseme_O`, `viseme_U`, `viseme_I`, `viseme_E`). The runtime finds them by name.
3. **Export:** File > Export > glTF 2.0 (.glb). Turn on Apply Modifiers, Shape Keys and +Y Up. Turn off Draco compression, which the site does not load.
4. **Use it:** save as `w2s-site/buddy-models/ruby.glb` and/or `max.glb`.
5. **Build and serve:** `npm run build`, then `npm run serve`.
6. **Refresh the pictures:** run `npm run posters` (re-renders the static pictures from your models), then `npm run build` again.
7. **Check it:** `npm run turnaround` writes front, three-quarter, side, back and face renders to `w2s-site/audit/after/`, then run `npm run test:buddies`.

**What works with a Blender export today.** A model without the `w2s-1` extras runs as a "generic" model. It gets lip sync from its shape keys, blinking, spin, hops, the switch animation and pokes. It does not yet get arm and head gestures, eyelid nodes, gaze or the hair swing, because those drive `w2s-1` nodes that have no rest rotation. Blender armature bones do have rest rotations. Supporting a normal Blender armature is the first planned improvement below.

## 10. Deploying

Upload `w2s-site/dist/` to any static host. `_headers` is in the Cloudflare Pages and Netlify format: it sets security headers, long caching for `/assets/*` and limits the microphone to the site. Pages are folders with an `index.html`, so URLs end in a slash. `404.html` is the not-found page.

## 11. Rules to keep

- No requests to other domains: the privacy notice promises it. Self-host anything new.
- Keep the labels the Sprint slide decks and the learner guide refer to: Next, Go, Help me, Record, Send it, Speech Mode, and the scene names.
- Keep the internal Buddy ids `mila` and `rio` and the `w2s:*` events.
- Do not change the privacy notice, lesson content, Sprint tasks, game packs, URLs, page titles or structured data without a reason. Other material (the decks, the guide, the SEO work) depends on them.
- Never put an API key in the site folder. The Eachlabs key used earlier lives only in the old cloud workspace and should be rotated.

## 12. Known issues

1. **Share image and app icons are not in `dist/`.** Pages point to `/media/og.png`, `/apple-touch-icon.png` and `/icon-512.png`, but `sitebuild.py` clears `dist/` and does not make them. `icons.cjs` makes them; run `npm run icons` after every build until it is part of the build. The current live build and the earlier zips also lack them, so this package matches.
2. **The frame rate on a real phone has never been measured.** Open `/speech-mode/?fps=1` on a phone to measure it.
3. **Face size:** the face fills 42% of the stage width at 360x640 and 55% at 390x844, against a target of about a third.
4. **Keyboard layout untested on a real keyboard:** it was tested by shrinking the viewport. It has not been tested with a real on-screen keyboard or on iOS Safari.
5. **Help me on short phones:** at 360x640 the Help me card starts just below the chin; with the keyboard also open it covers the lower face.
6. **Tap dance hard to reach:** on phones the legs are behind the subtitle.
7. **Model quality:** the built-in models are about 60% of the way to a hand-sculpted film character. Closed eyelids read as domes, the open mouth is simple, hands are mitten-like, hair has no strand detail and colour edges on trims are slightly jagged up close.
8. **Old helpers:** `shots.cjs` and the root `audit.cjs` are old screenshot helpers. The `_previous/` files still contain the old cloud paths and will not run.

## 13. Planned improvements

In rough order:

1. **Support a normal Blender armature** in `buddies.js`. Apply gestures relative to each bone's rest rotation, map Mixamo, Rigify and Ready Player Me bone names, and drive eyelids from shape keys. Then a Blender character gets every gesture.
2. **Real lip sync from your own models:** use the viseme shape keys per word shape, and add audio-driven timing if recorded voices are added later.
3. **Make the share image and icons part of `sitebuild.py`** (known issue 1).
4. **Measure on real phones** (a budget Android, an iPhone) with `?fps=1`, then tune the quality steps.
5. **Remaining items from the phone audit (P2 in `AUDIT.md`):**
   - Larger Sprint tick boxes.
   - Fold the other Sprint days away by default.
   - Move the home try-it game higher.
   - Reserve the scrollbar gutter for narrow desktop windows.
   - Add a next step on Tutor view and the privacy notice.
   - Lighter Join placeholder.
   - Spanish glosses for XP, Scripted practice and Solo.
6. **Speech Mode polish:** keep the face clear when Help me is open on short phones, and make the tap dance reachable on phones.
7. **Join form:** add the Web3Forms key and WhatsApp number in `config.json` once they exist. Note that a Web3Forms key adds a request to another domain on submit, which the privacy notice should then mention.
